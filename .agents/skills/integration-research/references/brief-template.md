# 集成简报模板

写入 `docs/integrations/<slug>.md`。方括号为占位；未知写「待确认」，禁止臆造端点。

```markdown
# 集成简报：<依赖显示名>

| 字段 | 值 |
|------|-----|
| slug | `<slug>` |
| 触发源 | PRD `Fxx` / arch §8 / code-reviewer `P0-x` / 用户 |
| 类型 | protocol \| vendor \| hybrid |
| 可行性 | A \| B \| C \| D |
| 状态 | draft \| confirmed \| blocked \| superseded |
| 日期 | YYYY-MM-DD |

## 1. 目标与边界

- **要对齐的产品能力**：…
- **In Scope（首版真实路径）**：…
- **Out of Scope**：…（含：禁止 stub/mock 交付）

## 2. Integration Card（摘要）

- 仓内痕迹：…
- 宣称情况：无 / 有入口 / 文档宣称
- 环境：沙箱·账号·证书（具备 / 缺失 / 待确认）

## 3. 可行性结论

一句话 + 刻度理由（A–D）。若 C/D：列出阻塞与建议（撤入口 / 等材料 / 换依赖）。

## 4. 候选方案（2–3）

| 方案 | 来源（链接） | 契合本栈 | 风险 | 备注 |
|------|--------------|----------|------|------|
| 官方 SDK / 标准库 | URL | 高/中/低 | … | 优先 |
| 自研 HTTP + OpenAPI | URL | … | … | |
| 社区库 / 参考实现 | URL | … | 维护·许可证 | 不得仅凭 star |

**推荐**：方案 X。理由：…

## 5. 标准对接流程（推荐）

1. **配置与密钥**：配置项、密钥存放、轮换
2. **鉴权**：协议要点（如 client_credentials / bind DN / AK-SK）
3. **连通性探测**：最小只读调用与超时
4. **业务最小操作**：首版真实写/读（点名 API）
5. **失败语义**：超时、4xx/5xx、部分失败；**不得假成功**
6. **可观测**：日志字段、审计、metrics（若适用）

## 6. 契约要点（供 arch §8）

| 项 | 内容 |
|----|------|
| 依赖方 | |
| 协议 | HTTPS / LDAP / SMTP / … |
| 认证 | |
| 超时 / 重试 / 幂等 | |
| 失败语义 | |
| 数据归属 | 谁为真理源 |
| 参考链接 | 官方文档、OpenAPI、本简报 |

## 7. 真实验收草案（待确认 → PRD）

> 给定 <前置真实配置/权限>，当 <真实操作>，则 <可观察结果>；
> 依赖 <X> 不可用时，返回 <明确错误/降级策略>，不得返回成功态。

至少 2 条。标注：`（待确认）`。

## 8. 首版真实切片建议

- 切片名：…
- 端到端路径：… → … → …
- 明确不做：…

## 9. 阻塞项

- [ ] …
- [ ] …

## 10. Followups

- [ ] 用户确认后写入 `docs/arch.md` §8
- [ ] 用户确认后修订 PRD 分片验收/状态
- [ ] plan：环境就绪 / 真实切片排期
- [ ] 实现或撤入口；必要时再跑 code-reviewer
```
